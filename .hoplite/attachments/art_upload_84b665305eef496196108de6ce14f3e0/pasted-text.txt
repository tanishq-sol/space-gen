I've planned this out below as 18 tasks you can paste to your agents, in 5 waves. First, the repo is further behind than `.agent-state/PROGRESS.md` says:

- **The frontend doesn't install as committed.** `npm ci` fails because Pascal needs `three@^0.186` and the repo pins `^0.185`. With `--legacy-peer-deps`, `tsc` and `next build` both pass.
- **Pascal is only used as a viewer.** The editor package isn't wired in, item nodes use the wrong fields (`modelUrl` where Pascal expects `asset.src`), and the room is seeded from hardcoded sample data on every load.
- **The splat doesn't show in the editor.** Pascal's viewer uses three.js's WebGPU renderer, and I haven't confirmed that Spark's splat renderer works with it. The "hide region" controls only store data; they don't mask anything.
- **Nothing is saved.** A reload loses all edits. The backend returns demo data for every scene ID, and three file routes have a path traversal hole.
- **AI changes the scene directly.** There's no proposal, validation or accept/reject step. "Photo-to-3D" is a keyword match against 7 placeholder models.
- **About the two projects you linked:** Pascal (MIT) is the right base, and it already has wall, slab, zone, door, window, item, scan and measurement nodes, plus undo and IndexedDB saving. PlayCanvas Editor needs the playcanvas.com backend, so don't embed it. PlayCanvas's SuperSplat and `splat-transform` are better suited for cleaning and converting splats.
- **On converting splats to meshes:** a full room mesh won't be editable in any useful way. A better approach is to keep the splat as the photoreal background, fit the walls, floor and openings as editable Pascal shapes, and replace furniture with GLB models. Use meshes only for collision checks.

I didn't change the repo. The only thing I created is a gitignored `node_modules` from a test install.

## Wave 2 — reviewable room interpretation (Phase 2)

**T10 — Room structure from the scan** (branch `feat/room-structure`, backend)
```
Service plus job endpoint: from splat positions and opacity (with optional COLMAP points), compute: gravity alignment, floor plane (RANSAC), ceiling height, wall planes (Manhattan prior with a non-Manhattan fallback), room outline polygon, openings (gaps or low density in wall bands, plus optional image-based door/window detection). Every element gets a confidence value.
Output: RoomInterpretation (T04). Also suggest a scanToScene.
Tests: synthetic point clouds with known rooms (rectangle, L-shape, noise and floaters) must recover walls within tolerance; report the numbers. Run as a background job, not inside the HTTP request.
```

**T11 — 3D object detection** (branch `feat/object-detection-3d`, backend)
```
Detect objects in keyframes (open-vocabulary detector, e.g. Grounding DINO/OWLv2 + SAM 2, or Gemini bounding boxes as a fallback). Lift detections into 3D using COLMAP camera poses and splat depth (raycast/render depth), cluster across views into OBBs (center, size, yaw), and compute confidence from view agreement × detector score.
Output: RoomInterpretation.detections plus a MaskRegion for each detection.
Make it GPU-optional (CPU fallback slow but working). Evaluate on 2 real scans by hand-labelling OBBs; report IoU/recall in the PR.
```
